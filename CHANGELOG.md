- Added B1: a data pull layer (`agents/analyst/data_pull.py`) shaping seed data for `common/metrics.py`, with no KPI arithmetic outside it.
- Added B2: attribution breakdown by campaign/ad set/creative asset (`agents/analyst/attribution.py`), with an explicit `unattributed` bucket and top/bottom performer ranking.

- Completed B5/ANA-03: `build_conversion_drop_alerts` now requires both a threshold breach and a minimum sample-size floor before alerting; drops below the floor are suppressed and logged with their counts instead. Added `mark_stale` to flag KPI figures whose source data is older than 6 hours.
- Added B6: a weekly optimisation report (`agents/analyst/scheduler.py`) with concrete scale/pause/rewrite recommendations backed by figures, scheduled every Monday via APScheduler. The Analyst never executes any recommendation.
- Added B7: a no-op-safe Langfuse tracing wrapper (`common/tracing.py`). Tracing is a clean no-op when `LANGFUSE_PUBLIC_KEY`/`SECRET_KEY` are unset, and never crashes the caller if Langfuse is unreachable. Wired into `/report`, `/observe`, `/weekly_report`, and `/alerts`.
- Added the central `agent_logs` store (`common/db.py`, SQLAlchemy, no Alembic): `log_action` now dual-writes to Postgres/SQLite in addition to the local JSONL file, with a fast connection timeout and a logged fallback if the database is unreachable so an agent never crashes or hangs because of a database outage.
- Added `tests/conftest.py` forcing the test suite onto an in-memory SQLite database, independent of local `.env` contents.
- Added `/optimisation_report`, a manual Telegram command to preview the B6 weekly report without waiting for the Monday 08:00 job.
- Closed ticket 7.1 (Phase A audit and log store): added `scripts/generate_test_logs.py`, simulating one realistic action per non-Analyst agent (Commander, CRM Keeper, Qualifier, Content Strategist, Media Buyer, Closer) through the same shared `log_action`, since those agents do not exist in this repo yet. `tests/test_multi_agent_logging.py` proves all 6 rows land in `agent_logs` with every mandatory field populated. Updated `docs/LOG_AUDIT.md` to distinguish "pass (simulated)" — pipeline proven, agent not built — from a real pass, and recorded that the Media Buyer and Closer agents (reviewed directly from their own repos) exist but never call a validated `log_action`, which is their actual Phase A gap, not a documentation one. Also recorded that a second, separate "Phase A" scaffold was found in a colleague's own repo and is being consolidated into this one per the work plan's "one shared repo, no forks" rule.
- Fixed `.env`'s `DATABASE_URL` (`postgresql://` -> `postgresql+psycopg://`, the scheme our `psycopg`-based dependency actually needs) and validated the central `agent_logs` store against a real local PostgreSQL 17 instance for the first time: schema creation, all 6 simulated agent logs written with zero database-write failures, confirmed by direct query.
- Added the first real LLM call in the Analyst: `common/llm.py`, a no-op-safe DeepSeek wrapper (`litellm`, model `deepseek/deepseek-chat`) mirroring `common/tracing.py`'s pattern -- a blank `DEEPSEEK_API_KEY` makes generation a clean no-op, and any API failure is caught, logged, and returns `None`, never raised. Every call is traced as a Langfuse generation (B7) and logged through the mandatory log format, success or failure. Wired into the weekly optimisation report (B6): `build_weekly_optimisation_report` now ends with a 2-3 sentence plain-language summary of that week's scale/pause/rewrite recommendations and overall ROAS, generated from the same figures already shown -- never used to calculate a KPI, only to explain one in prose, consistent with `common/metrics.py` staying the only place KPI math happens.
- Added `tenacity` retries (3 attempts, exponential backoff) to the DeepSeek call in `common/llm.py`, matching the Media Buyer and Closer agents' own retry pattern on external calls (per `AGENT_LIBRARIES_ADDENDUM.md`: nothing in the stack retried transient failures before this).
- Fixed a test-isolation gap in `tests/conftest.py`: once real Langfuse/DeepSeek credentials were added to a developer's `.env` for manual testing, the automated suite silently started making real (slow, billed) network calls instead of exercising the no-op paths. `LANGFUSE_PUBLIC_KEY`/`LANGFUSE_SECRET_KEY`/`DEEPSEEK_API_KEY` are now forced blank for the whole session, same treatment as `DATABASE_URL` already got.
- Closed the remaining gaps against the Phase B "features to build" list, verified line by line against the actual code (not just docs) of CRM Keeper, Media Buyer, Content Strategist, and Commander:
  - Added `agents/analyst/live_data.py`: best-effort HTTP clients for CRM Keeper (`GET /crm/leads/stage/{stage}` across all 7 stages) and Media Buyer (`GET /performance/last-7-days`), `httpx` + `tenacity` retries, `None` on any failure.
  - `data_pull.py::pull_kpi_report` is now hybrid: CPL, CPQ, CPQL, and stage_conversion_rate are pulled live when both CRM Keeper and Media Buyer are reachable (never partially -- one down means both fall back together), everything else stays on the seed dataset. Every metric now carries a `source` field (`"live"`/`"simulated"`); ROAS and B2 attribution are permanently `"simulated"` because neither upstream API exposes deal value or per-campaign spend (verified against their Pydantic models directly).
  - Added week-on-week KPI comparison: `common/db.py`'s new `KpiSnapshot` table, `reporting.py::save_kpi_snapshots` (written once a week by the Monday job, not on every manual `/report`) and `attach_week_over_week` (looked up by `/report` and `/weekly_report`). `format_report_for_telegram` now shows a `▲/▼ delta vs last week` suffix, or `(no prior snapshot)` on the first run.
  - `scheduler.py::start_scheduler` now runs two jobs instead of one: the existing Monday weekly report (now also snapshotting KPIs), and a new anomaly watch every 6 hours that pushes an alert automatically the moment one fires -- silent otherwise, never an empty "all clear" message. Both job bodies were extracted to module-level `run_weekly_report_job`/`run_anomaly_watch_job` so they're directly testable without a running `AsyncIOScheduler`.
  - Added `agents/analyst/content_strategist_notify.py`: best-effort call to Content Strategist's `/cro-analysis` for every flagged landing page. Documented, not hidden: their endpoint accepts only a bare `conversion_rate` float with no page identifier or `client_id` (verified against their actual `api.py`/Pydantic models), so Content Strategist itself cannot know which page a given call is about -- the Analyst logs the correlation on its own side only.
  - Investigated sending the weekly report to a real Commander instead of Telegram: Commander's `POST /event` routes an event *to* an agent in its own registry, it does not receive one addressed to itself, and `POST /text` runs input through its LLM/operator-memory pipeline, unsuited to a structured report (verified against Commander's actual `api.py`/`core/agent.py`). No code change made here -- documented as a real limitation in `agents/analyst/README.md` rather than forcing a fake integration.
- Made `common/llm.py` provider-agnostic instead of DeepSeek-only: `active_model()` reads `LLM_MODEL` (default `deepseek/deepseek-chat`), and `PROVIDER_API_KEY_SETTINGS` maps a model's provider prefix to the right settings key (`DEEPSEEK_API_KEY`, `GEMINI_API_KEY`, `OPENAI_API_KEY`, `OPENROUTER_API_KEY`) -- switching provider is a `.env` change, never a code change. `tests/conftest.py` blanks all four for the whole suite, same treatment `DEEPSEEK_API_KEY` already had.
- Fixed a real bug this surfaced: the weekly report's AI summary was silently truncated to a handful of words on `gemini-2.5-flash`. Root cause -- Gemini's "thinking" models count hidden reasoning tokens against the same `max_tokens` budget as the visible answer, so the old default of 300 left almost nothing for the actual response, with no error raised. Raised `generate_text`'s default `max_tokens` to 1024.

  - **C2 (predictive ROAS)**: `agents/analyst/predictive_roas.py::project_roas` projects closed-won revenue as a range (never a point estimate) over the next N days, from the current SQL pipeline volume and historical booking/close rates (`common/metrics.py::confidence_interval_on_rate`, already built). Below the ANA-03 volume floor, returns `sufficient_data=False` instead of a fabricated number.

  - **C4 (scoring feedback)**: `agents/analyst/scoring_feedback.py::build_calibration_proposals` compares each scoring dimension's average score between closed-won leads and everyone else, and proposes decreasing the weight of whichever dimension is both the most heavily weighted and the least predictive of the real outcome -- never auto-applied, only a proposal with evidence. Stands in for Content Strategist's real `content_assets` table (CCS-03, not built in their repo) via a new `seed_data.py::_build_content_variant_rows`, with three variant pairs deliberately matching each of the three decision-rule branches.

Wired into `build_weekly_optimisation_report` right after the summary is generated, so it runs every Monday.
